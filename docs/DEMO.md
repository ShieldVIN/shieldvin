# The ninety-second demo

One vehicle with a history it can prove, one without — and a verifier who never sees either
record. Everything below runs against state generated by the compiled circuits
(`npm run demo:export`), and the same walkthrough works on the live page:
**<https://vinpassport.github.io/VINPassport/>**.

This is written as a script with timestamps because it doubles as the video's shot list, but it is
equally the order to click through live for anyone evaluating the repository.

---

## 0:00 — The problem, in one breath

> When you buy a used car, the history you are shown is whatever the seller chose to print — and
> the fix cannot be "publish everything", because a full vehicle history is commercially sensitive
> to the seller and personally identifying to the owner. From September 2032, Regulation (EU) 2026/1738 makes a
> digital vehicle passport mandatory anyway. It has to be checkable. It does not have to be public.

*On screen: the scan page landing — two demonstration vehicles.*

## 0:15 — Vehicle A: a history it can prove

*Tap Vehicle A.*

> This is what a buyer sees after scanning the QR on a car. Four verdicts:
> **never written off, no reported accidents, one keeper, mileage under 150 000 km.**
> Notice what is *not* on this page: no VIN, no reading, no dates, no file.

*Tap "Never written off" open.*

> Behind every tick is a claim on Midnight's public ledger. A zero-knowledge proof was accepted
> that could not have been produced unless the hidden value satisfied the bound — and the claim
> records **the exact version of the record it was proven against**, so if the field is ever
> updated, this verdict visibly goes stale instead of quietly going wrong.

## 0:35 — Vehicle B: the honest negative

*Back, tap Vehicle B.*

> Same page, different car. Mileage under 200 000 — proven. But look at the clean-history rows:
> **not proven**. This vehicle's write-off proof would abort inside the circuit, so no claim
> exists — and the page renders that as exactly what it is. Not proven is not a no; it is a
> question the seller has declined to answer. One transaction would answer it, if it were true.

## 0:55 — What is underneath

*On screen: the contract source, then the test run.*

> Five circuits in Compact, Midnight's zero-knowledge language. Every field of the passport is a
> separate private commitment under an integrity rule fixed at creation — mileage, accidents,
> keepers, write-off status can never fall. Sixty-seven contract tests run against the compiled
> circuits, and we mutation-check them: delete a rule from the contract and exactly the tests for
> that rule fail, nothing else.

## 1:15 — Close

> Proofs are built and signed locally — the fee sponsor never sees a private value. The record
> stays with the vehicle; the verdicts live on the chain, where anyone can check them.
> VINPassport: the vehicle passport the EU mandates, without the disclosure it forbids.

*On screen: repository URL and the scan page URL.*

## Reproducing the demo state

```bash
npm install
npm test              # 67 contract + 10 app + 24 SDK, all green
npm run demo:export   # regenerate app/scan/demo-data.json from the circuits
npm run serve:scan    # the same page as the live URL, locally
```

The exported ledger is asserted clean of every private value — the readings and salts exist only
inside the generating process. What the page renders is exactly what an observer of the chain
would see, which is the point of the demo: the verdicts are checkable, the record is not
recoverable.

## Production notes (for filming)

- Film against **pre-generated state**, never a live proving run: panel-scale proofs take
  seconds, but nothing in a demo should depend on network weather.
- The phone shots are real — the page is mobile-first and the deep links
  (`?v=<vin-hash>`) are exactly what a printed QR resolves to.
- Keep the trust-gap sentence in: a tick means *proven against the anchored record,
  attributable, tamper-evident* — never "fraud is impossible". Overclaiming here costs more
  than the claim earns.
